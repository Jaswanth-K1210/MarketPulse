# GHAN-Lite Impact Scorer — Design Spec

**Date:** 2026-07-13
**Base paper:** Breaking down financial news impact: A novel AI approach with geometric hypergraphs (arXiv:2409.00438)
**Status:** Approved

## Problem

MarketPulse's impact scoring appears ML-driven but is not. `app/services/impact_calculator.py`
delegates to a LightGBM model (`app/ml/risk_scorer.py`) that is trained exclusively on 3,000
synthetic samples generated by a hand-written formula
(`risk = severity*0.4 + |sentiment|*0.3 + tier*0.15 + ...`). Its `retrain()` method accepts
`feedback_rows` and ignores them. The model has never seen a real market outcome.

## Goal

Replace the synthetic-trained scorer with a hypergraph-attention model (GHAN-inspired,
implemented via star expansion in PyTorch Geometric) trained on real news → price-movement
data, behind the same `impact_calculator` interface. Produce a before/after evaluation
suitable for a minor-project report.

Explicitly out of scope: faithful reimplementation of the paper's geometric component;
live retraining; any change to the news ingestion pipeline, API surface, or frontend.

## Decisions (locked)

| Decision | Choice |
|---|---|
| Ticker universe | S&P 100 |
| Prediction target | 3-class direction of 3-day abnormal return vs SPY: up (>+1%), flat, down (<−1%) |
| Model implementation | PyTorch Geometric, star expansion of hyperedges (GATConv) |
| News corpus | FNSPID (Hugging Face); prices via yfinance |
| Text embeddings | FinBERT CLS embeddings via existing `app/ml/finbert_service.py`, cached to disk |
| Splits | Temporal: train/val/test partitioned by article date (no leakage) |

## Components

### 1. Dataset builder — `app/ml/ghan/dataset.py`

- Downloads/streams FNSPID, filters to S&P 100 tickers (static list checked into
  `app/ml/ghan/sp100.py`).
- One sample per (event, ticker) pair. An event is one article; its tickers are the
  FNSPID-tagged symbols intersected with the universe.
- Label: cumulative return of the ticker over the 3 trading days following publication,
  minus SPY's return over the same window. Classes: up (>+1%), flat ([−1%, +1%]), down (<−1%).
- Articles published after market close attribute to the next trading day.
- FinBERT CLS embedding per headline, computed once and cached (`data/ghan/embeddings.npz`
  + parquet index). The builder is resumable: raw download, price cache, and embedding
  cache are separate idempotent stages.
- Output: `data/ghan/dataset.parquet` (event id, ticker, date, label, embedding index)
  plus split boundaries (e.g., train ≤ 2021-12, val 2022-01..2022-06, test ≥ 2022-07 —
  exact dates set from actual corpus coverage at build time).

### 2. Graph builder — `app/ml/ghan/graph_builder.py`

- Star expansion: each event becomes a virtual event node; edges connect it to
  (a) its mentioned tickers and (b) their first-degree supply-chain neighbors from the
  existing relationship graph (`app/services/database.py` relationships table). The
  neighbor expansion is what makes edges genuinely hyper (multi-ticker) and reuses
  MarketPulse's differentiating data.
- Bipartite hetero graph: ticker nodes carry learned embeddings (nn.Embedding, dim 64);
  event nodes carry FinBERT embeddings (dim 768, projected to 64).
- Batches are per-time-window subgraphs so no future event influences a past prediction.

### 3. Model — `app/ml/ghan/model.py`

- `GATConv((64, 64), 32, heads=4)` → `GATConv((128, 128), 64)` over the bipartite graph
  (message passing ticker↔event both directions).
- Head: MLP over concat(event repr, ticker repr) → 3 logits.
- Class-weighted cross-entropy (flat class dominates). Dropout 0.3, AdamW, early stopping
  on val macro-F1. Runs on MPS/CPU.
- Explainability: per-prediction attention weights exposed as
  `[{"neighbor": ..., "weight": ...}]` — mirrors the paper's XAI claim.

### 4. Training — `scripts/train_ghan.py`

- CLI: `--epochs --lr --subset N` (subset flag for smoke tests).
- Saves `app/ml/models/ghan.pt` (weights + ticker vocab + config) and
  `app/ml/models/ghan_metrics.json` (train/val curves, test metrics).

### 5. Evaluation — `scripts/evaluate_impact_models.py`

Runs three scorers over the held-out test period and emits a markdown report
(`docs/ghan_evaluation.md`) with accuracy, macro-F1, and per-class precision/recall:

1. **Current system**: rule/synthetic-LightGBM scorer, its [0,1]·direction output mapped
   to classes with the same ±1%-equivalent thresholds (calibrated on val split).
2. **FinBERT-sentiment-only baseline**: sign of sentiment score → class.
3. **GHAN-Lite**: argmax of class probabilities.

Stretch (only if time remains): P&L comparison via `app/services/trading/backtester.py`.

### 6. Integration — `app/ml/ghan/scorer.py` + edit to `impact_calculator.py`

- `GHANScorer.score(article_meta, relationship, event_type)` returns
  `{"risk_score": float, "explanation": list}` — same contract as `risk_scorer`.
- Signed impact = P(up) − P(down); `risk_score` = |signed impact|, direction taken from
  the sign (replacing the current sentiment-sign hack).
- Fallback chain in `impact_calculator`: GHAN (if `ghan.pt` exists and torch imports) →
  LightGBM → rules. The app must start and serve normally with no model file present.
- Inference path for live articles: FinBERT embedding on the fly, ticker looked up in
  vocab; unknown tickers fall back to LightGBM.

### 7. Testing — `tests/test_ghan.py`

- Unit: abnormal-return labeler (known price fixtures → expected classes), graph builder
  (event with 2 tickers + 1 supply-chain neighbor → correct star), scorer contract
  (output shape/range, fallback when model missing).
- Smoke: `train_ghan.py --subset 200 --epochs 2` completes and produces a loadable model.

## Risks

- **FNSPID size**: multi-GB download; mitigated by streaming filter + resumable stages.
- **Sparse hyperedges**: if S&P 100 filtering yields mostly single-ticker events, the
  supply-chain neighbor expansion (§2) is the mitigation; if still sparse, widen the
  return window or universe — decide at dataset-stats checkpoint before training.
- **Class imbalance / label noise**: class weights + macro-F1 as the headline metric.

## Report narrative (for the minor project)

"The existing system's ML scorer was trained only on rule-generated synthetic data —
rule-laundering, not learning. I built a labeled dataset of real news→abnormal-return
outcomes, implemented a hypergraph-attention model per arXiv:2409.00438 (star-expansion
adaptation), integrated it behind the existing scoring interface with graceful fallback,
and evaluated before vs. after on a held-out time period."
